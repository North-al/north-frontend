# Routing

Vue Router 路由组织、权限控制和页面生命周期相关规范。

优先遵循项目现有路由体系，不擅自切换权限模式。

## 1. Route Organization

如果项目没有既定约定，优先考虑集中式路由组织。

参考结构：

```text
src/router/
├── index.ts
├── routes.ts
└── modules/
    ├── user.ts
    └── order.ts
```

职责：

- `index.ts`：路由实例创建、初始化和统一配置。
- `routes.ts`：集中组织路由模块。
- `modules/`：按业务模块维护路由定义。

该结构是新项目的参考，不强制改造已有路由组织。

## 2. Permission Architecture

开发权限相关功能前，必须先理解项目现有权限体系。

常见模式包括：

### Dynamic Routes

动态路由模式：

- 路由数据存储在后端。
- 后端接口返回路由数据。
- 前端根据返回数据动态注册路由。
- 根据项目约定处理组件映射、菜单和权限。

### Static Routes

静态路由模式：

- 前端定义全部路由。
- 路由 `meta` 中定义权限字符。
- 后端返回用户具有的权限字符。
- 前端根据权限字符过滤路由、菜单或操作入口。

两种方式都可以使用，但不能擅自混合两套模式。

必须遵循项目现有权限体系。

如果需要调整权限架构，应先分析现状和影响范围，并与用户明确沟通。

## 3. Route Metadata

路由元信息遵循项目已有约定。

如果项目使用静态路由权限模式，权限字符应与后端返回的权限数据保持一致。

不要随意新增一套与现有权限字段重复的定义。

菜单、路由、按钮权限应遵循项目现有数据结构和实现方式。

## 4. Page Data Fetching

页面数据请求时机根据实际依赖和生命周期决定。

可以在合适的场景中：

- `setup` 阶段请求。
- `onMounted` 中请求。
- 路由参数变化时请求。
- 使用 Hook 管理请求和状态。

不强制所有请求都放在 `onMounted` 中。

也不要求所有请求都必须在组件初始化阶段执行。

应当根据数据是否依赖 DOM、路由参数、用户交互以及业务状态决定。

## 5. Navigation and Cleanup

页面离开不意味着所有请求和资源都需要取消。

页面私有的轮询、事件监听和第三方实例，可以根据其生命周期进行清理。

全局共享的 WebSocket、订阅和请求不能因为某个页面卸载就被无条件关闭。

资源清理应遵循资源所有权和实际业务生命周期。

## 6. Existing Permission System

修改路由或权限功能前，检查：

- 路由注册方式。
- 路由模块组织。
- 路由元信息。
- 菜单数据来源。
- 后端权限数据结构。
- 动态组件映射方式。
- 路由守卫和登录流程。

理解完整调用关系后再修改。

不要只修改路由配置，而忽略菜单、权限和页面访问之间的关联。
