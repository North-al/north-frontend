# UI and Styling

Vue 项目的 UI、样式、组件库和响应式布局规范。

视觉设计应当服务于产品定位，不固定套用某种设计风格。

## 1. Existing Styling System

优先遵循项目现有样式方案。

不要擅自切换：

- UnoCSS。
- Tailwind CSS。
- CSS。
- SCSS。
- CSS Modules。
- 其他项目已有样式体系。

如果项目已经使用某种样式方案，就继续使用，不额外引入另一套体系。

## 2. UnoCSS / Tailwind CSS

项目使用 UnoCSS 或 Tailwind CSS 时，优先使用原子类。

遵循：

- 简单样式优先直接使用原子类。
- 不为几条简单样式额外创建 CSS 文件。
- 重复且复杂的样式可以适当抽取。
- 遵循项目已有主题变量和设计 Token。
- 优先复用项目已有的样式工具和约定。
- 不为了消除重复类而创建过度抽象的样式组件。

复杂样式是否抽取，应根据复用范围和维护成本决定。

## 3. Component Library

优先使用项目已有组件库。

没有明确 UI 设计要求时，尽可能使用组件库提供的组件。

存在明确 UI 设计要求时：

1. 先检查组件库是否存在合适的基础组件。
2. 判断能否通过配置、Props 或 Slot 满足设计要求。
3. 必要时进行二次封装。
4. 评估二次封装的复杂程度。

二次封装的复杂度不能超过自行实现的复杂度。

如果封装成本更高，直接自行实现。

不要为了复用而增加不必要的封装层。

## 4. UI Design

UI 风格根据产品定位、目标用户和实际设计要求决定。

不固定使用：

- 现代简约。
- Material Design。
- Cupertino。
- 某一种固定的卡片布局。
- 某一种固定的后台管理系统风格。

没有明确设计要求时，根据产品类型和组件库能力合理设计。

存在明确设计要求时，优先遵循用户提供的设计参考、设计规范和现有页面风格。

不要给所有项目套用同一套默认视觉模板。

## 5. Responsive Layout

响应式布局以项目实际使用场景为主。

使用 UnoCSS 或 Tailwind CSS 时，可以对部分布局进行合理适配，例如：

- 卡片布局。
- 列表布局。
- 多列内容区域。
- 内容间距。
- 局部布局切换。

没有明确要求时，不默认要求所有页面适配所有设备。

根据实际目标设备和产品使用环境决定断点和布局策略。

不要为了响应式而增加没有必要的复杂布局逻辑。

## 6. Theme and Design Tokens

遵循项目已有的主题变量、颜色系统、字体、间距和组件规范。

不要在已有设计 Token 的项目中随意写入大量重复的固定值。

新增样式时，应优先使用项目已有变量。

确实需要新增设计 Token 时，先检查现有主题体系，避免出现多套含义相同的变量。

## 7. Custom Components

自定义组件应有明确的 UI 职责。

简单样式不需要额外抽取组件。

复杂且重复的 UI 结构可以抽取。

对于图标、内容区域等需要高度自由定制的部分，优先考虑 Slot，而不是不断增加 Props。

## 8. Visual Quality

界面设计需要考虑：

- 信息层级。
- 内容密度。
- 交互反馈。
- 状态表达。
- 可读性。
- 一致性。
- 实际使用场景。

不要为了视觉效果增加没有实际价值的装饰。
不要添加过多的说明文字或提示，提示可以采取tooltip的形式。
不要在没有设计依据时随意改变项目整体视觉语言。
